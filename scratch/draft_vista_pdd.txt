MERGE SORT DAN SEQUENTIAL SEARCH BERBASIS WEB 
 
ABSTRAK 
1 ABSTRAK 
Pengelolaan data praktikan Fisika Dasar di Fakultas Teknik Universitas Mulawarman 
sebelumnya menggunakan beberapa file spreadsheet terpisah. Kondisi tersebut membuat 
proses pencarian, pengurutan, presensi, penilaian, dan rekapitulasi data kurang terpusat 
serta berisiko menimbulkan duplikasi dan kesalahan pengolahan. Penelitian ini bertujuan 
membangun sistem pengelolaan data praktikan berbasis web serta menerapkan Merge 
Sort dan Sequential Search  pada proses pengurutan dan pencarian data. Penelitian 
menggunakan metode Waterfall yang mencakup analisis kebutuhan, perancangan, 
implementasi, pengujian, dan evaluasi. Sistem dikembangkan menggunakan Laravel dan 
MySQL. Data penelitian mencakup 538 data praktikan tahun akademik 2025 serta dataset 
sintetis berukuran 100, 500, 1.000, dan 5.000 entri. Pengujian fungsional menggunakan 
Black Box Testing, sedangkan pengujian kinerja mengukur waktu eksekusi, penggunaan 
memori, jumlah iterasi, dan jumlah perbandingan. Sistem menjalankan 50 pengujian 
utama dan 10 warm-up pada setiap kombinasi metode serta skenario, kemudian 
membersihkan outlier menggunakan Interquartile Range . Sistem menggunakan 3.071 
data bersih dari 3.200 hasil pengujian utama setelah mengeluarkan 129 outlier. Hasil 
pengujian fungsional menunjukkan bahwa seluruh fitur utama berjalan sesuai rancangan. 
Merge Sort menghasilkan waktu 0,38 – 0,59 ms pada 100 data dan 27,66 – 65,07 ms pada 
5.000 data, dengan penggunaan memori meningkat dari 6,63 KB menjadi sekitar 301,87 
KB. Sequential Search menghasilkan waktu 0,01 – 0,06 ms pada 100 data dan 0,01 – 4,53 
ms pada 5.000 data, dengan memori stabil pada 0,37 – 0,50 KB. Kedua algoritma 
menghasilkan waktu dan penggunaan memori lebih rendah daripada MySQL ORDER BY 
dan WHERE/LIKE pada lingkungan pengujian. Penelitian ini menerapkan kedua 
algoritma secara langsung dalam sistem praktikum dan membandingkan kinerjanya 
dengan baseline MySQL. Sistem yang dihasilkan mendukung pengelolaan data 
praktikum secara lebih terpusat, terstruktur, dan efisien. 
 
 
Kata kunci: Merge Sort, Sequential Search, MySQL, Sistem Praktikum Berbasis 
Web, Black Box Testing

ABSTRACT 
2 ABSTRACT 
The management of Basic Physics practicum participant data at the Faculty of 
Engineering, Mulawarman University previously relied on several separate spreadsheet 
files. This condition made searching, sorting, attendance recording, assessment, and data 
recapitulation less centralized and increased the risk of duplication and processing 
errors. This study aims to develop a web-based practicum participant data management 
system and implement Merge Sort and Sequential Search for data sorting and searching. 
The Waterfall method was applied through requirements analysis, design, 
implementation, testing, and evaluation. The system was developed using Laravel and 
MySQL. The research data consisted of 538 practicum participant records from the 2025 
academic year and synthetic datasets containing 100, 500, 1,000, and 5,000 entries. 
Functional testing used Black Box Testing, while performance testing measured 
execution time, memory usage, iteration count, and comparison count. The system 
performed 50 main runs and 10 wa rm-up runs for each combination of method and 
scenario, followed by outlier removal using the Interquartile Range. A total of 3,071 clean 
records from 3,200 main test results were used after removing 129 outliers. Functional 
testing showed that all main fe atures operated according to the design. Merge Sort 
required 0.38 – 0.59 ms for 100 records and 27.66  – 65.07 ms for 5,000 records, while 
memory usage increased from 6.63 KB to approximately 301.87 KB. Sequential Search 
required 0.01 – 0.06 ms for 100 records and 0.01 – 4.53 ms for 5,000 records, with stable 
memory usage of 0.37  – 0.50 KB. Both algorithms produced lower execution time and 
memory usage than MySQL ORDER BY and WHERE/LIKE in the testing environment. 
This study directly integrates both algorithms into a practicum system and compares their 
performance with MySQL baselines. The developed system supports more centralized, 
structured, and efficient practicum data management. 
 
Keywords: Merge Sort, Sequential Search, MySQL, Web -Based Practicum System, 
Black Box Testing

1.1 Latar Belakang 
Pelaksanaan praktikum merupakan kegiatan pembelajaran yang dirancang untuk 
memberikan pengalaman langsung kepada mahasiswa dalam menerapkan konsep teoretis 
melalui kegiatan eksperimen, observasi, dan analisis di laboratorium. Praktikum tidak 
hanya berfungs i sebagai sarana penguatan pemahaman akademik, tetapi juga sebagai 
media untuk melatih keterampilan teknis, ketelitian, serta kemampuan pemecahan 
masalah. Pelaksanaan praktikum membutuhkan sistem pengelolaan data yang terintegrasi 
dan terstruktur agar selu ruh proses administratif dan akademik dapat berjalan secara 
efektif. 
Pada praktikum Fisika Dasar di Fakultas Teknik Universitas Mulawarman, 
pengelolaan data menjadi aspek penting karena kegiatan ini melibatkan berbagai program 
studi, yaitu Teknik Elektro, Teknik Lingkungan, Teknik Industri, Teknik Geologi, Teknik 
Pertambangan, Teknik Sipil, dan Teknik Kimia. Praktikum Fisika Dasar terdiri atas Fisika 
Dasar 1 yang diikuti seluruh program studi tersebut serta Fisika Dasar 2 yang 
pelaksanaannya bergantung pada kebijakan dosen pengampu masing -masing program 
studi. Dalam operasionalnya, asisten praktikum bertanggung jawab terhadap pencatatan 
kehadiran, penilaian praktikum, serta penilaian laporan mahasiswa (praktikan) dari 
berbagai program studi, sehingga ketepatan pengelolaan data menjadi faktor penting 
dalam mendukung kelancaran  administrasi praktikum. Seluruh proses tersebut masih 
dilakukan menggunakan spreadsheet, sehingga pengolahannya sangat bergantung pada 
ketelitian manual dan rentan kesalahan. 
Pengelolaan data praktikan saat ini diawali melalui proses pendaftaran 
menggunakan Google Form yang disebarkan oleh ketua tingkat masing-masing program 
studi. Data awal yang dikumpulkan meliputi nama lengkap, NIM, email, dan nomor 
ponsel, kemudian diverifikasi kembali agar sesuai dengan data dosen pengampu sebelum 
digunakan dalam administrasi praktikum. Data penilaian dan presensi disimpan dalam 
Google Sheet secara terpisah berdasarkan program studi dan periode praktikum, sehingga 
pengelola harus menelusuri beberapa dokumen ketika membutuhkan informasi tertentu.

Pada satu periode praktikum tahun 2025, jumlah praktikan Fisika Dasar 1 
mencapai 382 mahasiswa, sedangkan Fisika Dasar 2 sebanyak 156 mahasiswa. Volume 
data tersebut berdampak langsung pada meningkatnya beban kerja pengelolaan, terutama 
dalam proses pengec ekan data seperti duplikasi NIM, sinkronisasi antar -sheet, serta 
pencarian manual menggunakan Ctrl+F. Meskipun jumlah praktikan tidak selalu 
meningkat setiap tahun, jumlah praktikan yang berubah -ubah mengharuskan sistem 
pengelolaan data mampu beradaptasi terhadap skala data praktikan yang bervariasi. 
Fragmentasi data praktikan ke dalam berbagai file menyebabkan proses pencarian 
dan pengurutan data menjadi kurang efisien. Asisten sering mengalami kesulitan dalam 
menelusuri informasi seperti nama, NIM, nilai, maupun status kehadiran karena data 
tersebar di banyak dokumen dengan format yang tidak seraga m. Selain itu, penggunaan 
spreadsheet secara terpisah berpotensi menimbulkan duplikasi data, ketidakkonsistenan 
informasi, serta kesalahan input, sehingga proses rekapitulasi nilai membutuhkan waktu 
dan ketelitian yang lebih tinggi. 
Permasalahan utama yang muncul adalah meningkatnya beban waktu dan tenaga 
dalam proses pengolahan serta penelusuran data, meskipun spreadsheet menyediakan 
fitur pengurutan dan pencarian data, mekanisme tersebut tidak terintegrasi lintas file dan 
tidak berjalan secara otomatis pada seluruh data praktikan. Asisten harus melakukan 
penyesuaian dan pemeriksaan pada setiap dokumen secara terpisah sebelum melakukan 
pencarian atau penyusunan nilai. Kondisi ini menyebabkan proses pengolahan data

berbasis web yang mampu mengelola data praktikum secara terpusat serta menyediakan 
mekanisme peng urutan dan pencarian data secara otomatis dan konsisten. Namun, 
penerapan sistem praktikum berbasis web sering kali belum disertai dengan evaluasi 
kinerja algoritma pengurutan dan pencarian yang digunakan, khususnya terhadap 
pengaruh ukuran dataset terhada p waktu eksekusi dan respons sistem. Oleh karena itu, 
diperlukan kajian lebih lanjut mengenai performa algoritma yang diterapkan dalam 
pengelolaan data praktikan berskala menengah.

entri membutuhkan algoritma pengurutan yang efisien secara komputasi. Algoritma

Merge Sort dipilih karena memiliki kompleksitas rata -rata O(n log n)  yang stabil dan 
konsisten pada berbagai kondisi data (terurut, acak, atau hampir terurut), serta bersifat 
stable sort  karena prosesnya membagi data menjadi bagian -bagian kecil sebelum 
digabung kembali  (Esau Taiwo et al., 2020) . Sementara itu, Sequential Search  dapat 
digunakan untuk melakukan pencarian data secara sederhana, tidak memerlukan data 
terurut terlebih dahulu atau kondisi awal tertentu, sehingga sesuai untuk diterapkan pada 
pencarian dinamis pada data yang baru di-input atau belum memiliki struktur tetap. 
Penerapan algoritma Merge Sort dan Sequential Search memberikan dasar bagi 
sistem praktikum berbasis web. Merge Sort memastikan data terus berada dalam kondisi 
terurut sehingga memudahkan proses pemeriksaan dan penyusunan administrasi, 
sementara Sequential Search  memberikan prosedur pencarian yang langsung, mudah 
dipahami, dan tanpa memerlukan penyesuaian struktur data yang rumit. Kombinasi ini 
memungkinkan proses penelusuran data praktikan, penyusunan nilai, serta rekapitulasi 
administrasi berlangsung lebih cepat  dan tidak lagi bergantung pada spreadsheet yang 
rawan kesalahan input maupun ketidakkonsistenan format. 
Sistem basis data seperti MySQL menyediakan mekanisme pengurutan dan 
pencarian data secara bawaan. Penelitian ini menerapkan algoritma Merge Sort  dan 
Sequential Search  pada lapisan aplikasi ( application layer ) untuk memproses data 
praktikan yang telah dimuat dari basis data. Pendekatan ini memungkinkan sistem 
mengatur proses pengurutan dan pencarian secara real-time pada data yang berada di 
memori aplikasi tanpa ketergantungan pada eksekusi query database secara berulang. 
Penerapan algoritma pada application layer juga memberikan kendali terhadap proses 
pengukuran waktu eksekusi, penggunaan memori, dan operasi internal algoritma. 
Sistem pengelolaan data berbasis web diharapkan dapat memusatkan proses 
administrasi Praktikum Fisika Dasar yang sebelumnya menggunakan beberapa file 
spreadsheet. Merge Sort  digunakan untuk mengurutkan data praktikan, sedangkan 
Sequential Search digunakan untuk mencari data berdasarkan NIM atau nama. Sistem 
juga menggunakan MySQL ORDER BY  dan WHERE/LIKE sebagai baseline untuk 
mengevaluasi kinerja kedua algoritma. Berdasarkan kebutuhan tersebut, penelitian ini 
disusun dengan judul “Sistem Pengelolaan Data Praktikan dengan Algoritma Merge 
Sort dan Sequential Search Berbasis Web”.

mahasiswa untuk menentukan efisiensi dalam pengurutan berdasarkan nilai 
akademik. Penelitian menunjukkan bahwa Merge Sort memiliki stabilitas tinggi 
dengan waktu pemrosesan yang konsisten meskipun ukuran data meningkat. 
Hasilnya, Merge Sort dinilai sesuai diterapkan pada sistem berbasis pendidikan 
yang memerlukan pengurutan data besar secara real-time (Aditya et al., 2025).

besar, sementara penggunaan memorinya relatif lebih tinggi. Temuan tersebut 
memperkuat relevansi penggunaan Merge Sort dalam sistem berbasis web yang 
memerlukan pengurutan data skala besar secara cepat dan stabil (Anggreani et al., 
2020).

2.2.3 Algoritma Sorting – Merge Sort 
Merge Sort adalah algoritma pengurutan yang menerapkan pendekatan divide and 
conquer dengan membagi data menjadi bagian -bagian yang lebih kecil, kemudian 
digabung kembali dalam urutan yang benar  (Esau Taiwo et al., 2020) . Algoritma ini 
menunjukkan kinerja yang konsisten pada berbagai ukuran data karena kompleksitas 
waktu pada kasus terbaik, rata-rata, dan terburuk sama-sama berada pada O(n log n) yang 
berarti bersifat stabil karena tidak mengubah urutan elemen yang bernilai sama. Merge 
Sort juga memiliki performa yang baik pada ukuran array kecil maupun besar, sehingga 
cocok digunakan untuk mengurutkan data dalam jumlah besar secara efisien . Selain itu, 
Merge Sort memerlukan ruang memori tambahan sebesar O(n) untuk membantu proses 
penggabungan data  (Liu Peike, 2024) . Penggunaan memori tambahan ini dapat 
dimanfaatkan dalam konteks sistem praktikum karena sebanding dengan jumlah data yang 
diurutkan dan memberikan keuntungan berupa hasil pengurutan yang stabil serta performa 
yang konsisten. Dengan karakteristik ini, Merge Sort sangat cocok untuk mengurutkan 
data praktikan seperti NIM, nama, dan nilai dalam sistem praktikum yang mengelola 
sejumlah besar praktikan dari berbagai program studi.

FUNCTION MergeSort(A) 
    n ← length(A) 
 
    IF n ≤ 1 THEN 
        RETURN A 
    END IF 
 
    mid ← n DIV 2 
 
    Left  ← A[0 ... mid - 1] 
    Right ← A[mid ... n - 1] 
 
    Left  ← MergeSort(Left) 
    Right ← MergeSort(Right) 
 
    RETURN Merge(Left, Right) 
END FUNCTION

FUNCTION Merge(Left, Right)

            i ← i + 1

            j ← j + 1 
        END IF

2.2.4 Analisis Kompleksitas Waktu Algoritma Merge Sort 
Kompleksitas waktu algoritma Merge Sort  ditentukan oleh proses pembagian 
array secara rekursif serta tahap penggabungan kembali sub-array yang telah terurut. 
Setiap proses pembagian menghasilkan dua bagian dengan ukuran relatif seimbang, 
sehingga kedalaman rekursi mengikuti pola logaritmik terhadap jumlah data. Setelah 
tahap pembagian selesai, proses merge dilakukan dengan membandingkan elemen dari 
masing-masing sub-array secara sistematis hingga terbentuk susunan data yang terurut. 
Struktur kerja ini menyebabkan jumlah operasi yang dilakukan tetap konsisten pada 
berbagai kondisi input data (Liu Peike, 2024). 
Berbeda dengan beberapa algoritma pengurutan yang performanya sangat 
dipengaruhi oleh susunan data awal, Merge Sort mempertahankan kompleksitas waktu 
yang sama pada kondisi terbaik, rata -rata, maupun terburuk karena seluruh elemen tetap 
harus melalui proses pembagian dan penggabungan. Karakteristik tersebut menjadikan 
Merge Sort  sebagai algoritma yang stabil dan dapat diprediksi, khususnya ketika 
digunakan pada sistem yang mengelola data dalam jumlah besar dan memerlukan 
konsistensi performa.

2.2.5 Algoritma Searching – Sequential Search 
Sequential Search  atau pencarian linier merupakan algoritma pencarian yang 
bekerja dengan membandingkan elemen data satu per satu secara berurutan hingga data 
yang dicari ditemukan atau seluruh data telah diperiksa dengan kompleksitas waktu O(n). 
Pada kondisi terburuk, yaitu ketika data yang dicari berada pada posisi terakhir, algoritma 
harus memeriksa seluruh data yang ada. Meskipun demikian, untuk skala data praktikum 
yang berkisar antara 500 –1.000 entri, waktu pencarian yang dihasilkan masih berada 
dalam batas yang dapat dimanfaatkan. Algoritma ini sesuai diterapkan pada sistem dengan 
data yang bersifat dinamis karena tidak memerlukan kondisi awal berupa data terurut 
maupun struktur indeks tambahan. Sequential Search  efektif digunakan pada aplikasi 
berbasis web yang membutuhkan proses pencarian sederhana dan fleksibel terhadap 
perubahan data (Wiguna, 2020). Dalam sistem praktikum berbasis web, pencarian data 
praktikan seperti NIM atau nama dilakukan pada data yang dapat berubah setiap periode  
praktikum, sehingga penggunaan Sequential Search mendukung proses pencarian yang

15 
 
konsisten, mudah diimplementasikan, dan terintegrasi langsung dengan logika 
pengolahan data sistem. 
Algoritma Sequential Search  dalam penelitian ini diimplementasikan untuk 
menggambarkan alur pencarian data secara sistematis pada lapisan aplikasi. Penyajian 
pseudocode di bawah ini bertujuan memberikan representasi mengenai tahapan pencarian 
mulai dari inisialisasi indeks hingga proses perbandingan data, sehingga mekanisme 
penelusuran elemen dapat dipahami secara terstruktur dalam konteks pengolahan data 
praktikum. 
 
FUNCTION SequentialSearch(Array, key) 
    n ← length(Array) 
    i ← 0 
 
    WHILE i < n DO 
 
        IF Array[i] = key THEN 
            RETURN i        // data ditemukan pada indeks ke-i 
        END IF 
 
        i ← i + 1 
    END WHILE 
 
    RETURN -1              // data tidak ditemukan 
END FUNCTION

pada application-layer processing yang bertujuan mengurangi ketergantungan terhadap 
query berulang ke server serta meningkatkan respons antarmuka pengguna. Dengan 
implementasi yang sederhana dan fleksibel, Sequential Search dapat menjadi alternatif

Pengujian kinerja algoritma pengurutan dan pencarian dilakukan melalui eksekusi 
berulang pada skenario yang sama agar hasil pengukuran lebih stabil dan objektif. 
Penelitian ini menjalankan 50 iterasi utama pada setiap kombinasi metode, ukuran 
dataset, dan skenario pengujian. Jumlah tersebut digunakan untuk memperoleh nilai

mean, median, dan standard deviation yang lebih konsisten serta mengurangi pengaruh 
fluktuasi antar -eksekusi. Pengulangan hingga sekitar 50 kali dinilai memadai untuk 
menghasilkan data statistik yang lebih stabil dan meminimalkan perbedaan hasil akibat 
variasi awal pengujian (Plevris & Solorzano, 2022) . Jumlah pengulangan yang terlalu 
sedikit dapat menghasilkan kesimpulan yang bias dan sulit direproduksi, sehingga 50 
iterasi dipilih sebagai keseimbangan antara reliabilitas hasil dan efisiensi komputasi 
(Werner et al., 2024). 
Sistem juga menjalankan 10 iterasi warm-up sebelum pengujian utama dimulai. 
Hasil warm-up tidak digunakan dalam perhitungan statistik karena proses tersebut 
bertujuan menstabilkan kondisi awal sistem serta mengurangi pengaruh pemuatan data, 
optimisasi runtime, dan caching awal. Pendekatan microbenchmark menempatkan proses 
pengukuran utama setelah fase stabil agar hasilnya lebih mewakili kondisi operasional 
sistem (Traini et al., 2023) . Penggunaan 10 iterasi warm-up sebelum pengukuran utama 
dapat mengurangi bias akibat fluktuasi awal pada proses eksekusi (Laaber et al., 2024) . 
Pengujian juga menggunakan beberapa ukuran dataset agar perubahan waktu eksekusi, 
penggunaan memori, jumlah iterasi, dan jumlah perbandingan dapat diamati seiring 
bertambahnya jumlah data (Pujiono et al., 2025). 
Data hasil pengujian dianalisis menggunakan statistik deskriptif berupa mean, 
median, dan standard deviation. Sistem menerapkan metode Interquartile Range (IQR) 
untuk mendeteksi nilai ekstrem berdasarkan batas Q1 − 1,5 × IQR dan Q3 + 1,5 × IQR. 
Data yang berada di luar batas tersebut ditandai sebagai outlier dan tidak digunakan dalam 
perhitungan statistik akhir, sedangkan data mentah tetap disimpan sebagai bagian dari 
hasil pengujian (Magar et al., 2024) . Data bersih kemudian digunakan untuk 
membandingkan kinerja Merge Sort dengan MySQL ORDER BY serta Sequential Search 
dengan MySQL WHERE/LIKE. Perbandingan tersebut menggunakan ukuran dataset dan 
skenario yang sama agar tren waktu eksekusi serta penggunaan memori setiap metode 
dapat dianalisis secara konsisten.

Laravel adalah framework PHP berbasis Model–View–Controller (MVC) yang

untuk pengembangan web, dapat disisipkan ke dalam HTML, dan dieksekusi di sisi server 
sehingga hasilnya dikirimkan ke browser sebagai HTML. Mekanisme ini memudahkan 
pengembang dalam membangun halaman web dinamis (Nova, 2025). 
HTML (HyperText Markup Language ) berfungsi sebagai bahasa markup untuk 
menyusun struktur dasar halaman web. Dalam Laravel, HTML dihasilkan melalui Blade 
templating engine sehingga pemisahan antara logika dan tampilan tetap terjaga, sekaligus 
memungkinkan penyusunan antarmuka yang rapi, responsif, dan mudah dipelihara agar 
dapat ditampilkan secara konsisten pada berbagai perangkat  (Rahmawati & Sumarsono, 
2024). Tampilan diatur menggunakan CSS (Cascading Style Sheets), yaitu bahasa desain 
visual yang mengontrol aspek estetika seperti warna, tipografi, jarak, dan layout. 
Pemisahan antara struktur dan tampilan memungkinkan pengelolaan desain yang 
konsisten tanpa mengubah HTML dasar, serta mendukung pengembangan sistem w eb 
yang responsif dan user-friendly dengan pengalaman pengguna yang lebih optimal 
--- PAGE 45 ---

(Tanjung et al., 2025) . Interaktivitas sistem diperkuat oleh JavaScript yang 
memungkinkan penambahan fitur dinamis seperti animasi, validasi formulir, dan

mampu meningkatkan kecepatan respons dan kualitas interaksi pengguna. JavaScript juga

Pada Gambar 3.3 DFD level 0, sistem digambarkan sebagai satu proses utama

3.6 Perancangan Pengujian  
Perancangan pengujian dalam penelitian ini bertujuan untuk memastikan bahwa 
sistem yang dibangun dapat berjalan dengan baik serta mengevaluasi performa algoritma 
yang digunakan. Proses pengujian terdiri dari dua bagian, yaitu pengujian fungsional 
sistem da n pengujian kinerja algoritma. Pengujian fungsional dilakukan menggunakan 
metode Black Box Testing  untuk memastikan setiap fitur sistem bekerja sesuai dengan 

--- PAGE 68 ---
 
46 
 
kebutuhan pengguna. Sementara itu, pengujian kinerja algoritma dilakukan untuk 
mengetahui performa algoritma pengurutan dan pencarian dengan melihat parameter 
seperti waktu eksekusi, penggunaan memori, serta respons sistem saat memproses data 
dengan jumlah yang berbeda.

hubungan antara data masukan dan keluaran tanpa melihat struktur atau kode program di

d. Prosedur Pengujian Algoritma.  
Penelitian ini membagi pengujian kinerja menjadi pengujian pengurutan dan

dan standard deviation yang lebih stabil. Sistem menjalankan 10 iterasi warm-up sebelum 
50 iterasi utama dilakukan. Hasil warm-up tidak digunakan dalam perhitungan statistik 
akhir karena tahap tersebut berfungsi mengurangi pengaruh kondisi awal, seperti

iterasi dan kondisi dataset yang sama agar hasil perbandingan tetap konsisten. 
Sistem menganalisis hasil pengujian utama menggunakan statistik deskriptif 
berupa mean, median, dan standard deviation . Sistem juga menerapkan metode 
Interquartile Range (IQR) untuk mendeteksi hasil pengujian yang berada di luar batas 
kewajaran. Perhitungan IQR menggunakan rumus berikut: 
IQR = Q3 − Q1 
Batas bawah = Q1 − 1.5 × IQR 
Batas atas = Q3 + 1.5 × IQR 
 
Hasil yang berada di bawah batas bawah atau di atas batas atas ditandai sebagai 
outlier dan tidak digunakan dalam perhitungan statistik akhir. Data mentah tetap disimpan

3.6.3 Teknik Pengukuran 
Penelitian ini menggunakan pendekatan pengukuran pada sisi server untuk 
memperoleh data performa algoritma secara lebih objektif dan konsisten. Proses 
pengukuran difokuskan pada dua indikator utama, yaitu waktu eksekusi dan penggunaan 
memori selama algoritma dijalankan. Seluruh hasil pengukuran kemudian dicatat secara 
terstruktur ke dalam basis data agar proses evaluasi dapat dilakukan kembali serta 
memungkinkan analisis kuantitatif terhadap performa sistem. 
1. Pengukuran Server-Side (PHP / Laravel). Pengukuran pada sisi server dilakukan 
untuk mendapatkan data kinerja algoritma secara langsung dari proses komputasi inti 
sistem, sehingga hasil pengukuran tidak dipengaruhi oleh faktor eksternal seperti 
tampilan antarmuka pengguna maupun kondisi jaringan. Parameter yang diamati 
dalam pengukuran ini meliputi: 
a) Waktu eksekusi algoritma, yang diperoleh dengan mencatat waktu sebelum dan 
sesudah algoritma dijalankan menggunakan fungsi  microtime(true), kemudian 
selisih waktu tersebut dikonversikan ke dalam satuan milidetik. 
b) Penggunaan memori, yang diukur melalui fungsi 
memory_get_peak_usage(true) untuk mengetahui konsumsi memori 
maksimum selama proses eksekusi algoritma berlangsung. 
c) Operasi internal algoritma, yaitu pencatatan jumlah perbandingan pada algoritma 
Merge Sort  serta jumlah iterasi dan perbandingan pada algoritma Sequential 
Search, yang direkam menggunakan variabel penghitung internal. 
d) Waktu eksekusi query baseline, yang diukur dengan mencatat waktu sebelum dan 
sesudah pemanggilan fungsi DB::select(). Hasilnya kemudian dianalisis 
menggunakan perintah seperti EXPLAIN untuk membandingkan kinerja algoritma 
pada sisi aplikasi dengan mekanisme pemrosesan standar pada SQL. 
2. Alat Bantu dan Otomatisasi Pengujian. Penelitian ini memanfaatkan beberapa alat 
bantu serta mekanisme otomatisasi untuk memastikan proses pengujian berjalan 
secara konsisten dan terkontrol. Otomatisasi diterapkan guna meminimalkan 
kesalahan manual serta mempercepat proses pengumpulan data sela ma eksperimen 
berlangsung.

a) Skrip otomatis berbasis Artisan Command  atau PHPUnit digunakan untuk 
menjalankan berbagai skenario pengujian secara berulang.

3.6.4 Lingkungan Pengujian 
Pengujian sistem dilakukan pada lingkungan lokal untuk memastikan proses 
pengukuran kinerja algoritma dan sistem berlangsung secara konsisten, terkontrol, serta 
meminimalkan pengaruh faktor eksternal. Penggunaan lingkungan lokal memungkinkan 
latensi jaringan dapat dihindari sehingga hasil pengujian lebih mencerminkan performa 
komputasi sistem yang sebenarnya. Selain itu, spesifikasi perangkat keras dan perangkat 
lunak yang digunakan dijaga tetap sama selama proses pengujian agar hasil evaluasi dapat 
direplikasi secara akurat. 
1. Spesifikasi Perangkat Keras: Sistem dijalankan pada sebuah laptop dengan sistem

4.5.1 Pembahasan Performa Merge Sort 
Hasil pengujian menunjukkan bahwa Merge Sort  mampu mengurutkan data 
praktikan pada lapisan aplikasi dengan waktu eksekusi yang meningkat seiring 
bertambahnya ukuran dataset. Dataset 100 menghasilkan waktu rata-rata di bawah 1 ms 
pada seluruh skenario, sedangkan dataset 5.000 menghasilkan waktu antara 27,659516 
ms dan 65,071449 ms. Peningkatan tersebut terjadi karena algoritma harus membagi, 
membandingkan, dan menggabungkan lebih banyak elemen ketika jumlah data 
bertambah. 
Skenario data sudah urut menghasilkan waktu terendah pada dataset 5.000, yaitu 
27,659516 ms. Skenario data duplikat menghasilkan waktu tertinggi sebesar 65,071449 
ms, sedangkan skenario Random Asc dan Random Desc  menghasilkan waktu masing -
masing sebesar 46,954765 ms dan 42,330955 ms. Perbedaan tersebut menunjukkan 
bahwa kondisi data memengaruhi proses perbandingan dan penggabungan meskipun 
Merge Sort tetap menggunakan tahapan pembagian data yang sama. 
Penggunaan memori Merge Sort meningkat dari sekitar 6,6328 KB pada dataset 
100 menjadi sekitar 301,8672 KB pada dataset 5.000. Kenaikan tersebut terjadi karena 
Merge Sort  membutuhkan ruang tambahan untuk menyimpan bagian kiri dan kanan 
selama proses pembagian serta penggabungan data. Nilai memori pada setiap skenario 
dalam ukuran dataset yang sama relatif serupa, sehingga jumlah data memberikan 
pengaruh lebih besar dibandingkan susunan awal data. 
Hasil tersebut sesuai dengan karakteristik Merge Sort  yang memiliki pola 
pemrosesan stabil pada berbagai kondisi data. Penelitian ini menerapkan Merge Sort  
secara langsung pada fitur pengurutan data praktikan berdasarkan program studi dan NIM. 
Penerapan tersebut tidak hanya menguji algoritma secara terpisah, tetapi juga 
menunjukkan penggunaannya pada sistem praktikum berbasis web. 
 
4.5.2 Pembahasan Performa Sequential Search 
Hasil pengujian menunjukkan bahwa waktu eksekusi Sequential Search  
meningkat ketika jumlah data yang diperiksa semakin besar. Dataset 100 menghasilkan 
--- PAGE 124 ---
 
102 
 
waktu rata-rata antara 0,005438 ms dan 0,064261 ms. Dataset 5.000 menghasilkan waktu 
antara 0,009820 ms dan 4,533239 ms sesuai dengan skenario pencarian yang dijalankan. 
Skenario kata kunci ditemukan menghasilkan waktu tertinggi pada dataset 5.000, 
yaitu 4,533239 ms. Skenario duplikat menghasilkan waktu sebesar 3,391112 ms, 
sedangkan skenario tidak ditemukan menghasilkan waktu sebesar 2,203659 ms. 
Perbedaan tersebut muncul karena jumlah elemen yang diperiksa dan jumlah hasil yang 
dikembalikan dapat berbeda pada setiap skenario. 
Skenario kata kunci kosong menghasilkan waktu paling rendah pada seluruh 
ukuran dataset. Sistem tidak menjalankan pemeriksaan kecocokan kata kunci secara 
penuh ketika pengguna tidak memasukkan kata kunci, sehingga waktu eksekusinya hanya 
meningkat dari 0,005438 ms pada 100 data menjadi 0,009820 ms pada 5.000 data. Kondisi 
tersebut berbeda dengan pencarian kata kunci yang mengharuskan sistem memeriksa NIM 
atau nama praktikan secara berurutan. 
Penggunaan memori Sequential Search berada pada kisaran 0,3672 KB sampai 
0,5000 KB. Nilai tersebut relatif stabil karena algoritma hanya menggunakan kata kunci, 
variabel penghitung, dan tempat penyimpanan hasil pencarian. Sequential Search tidak 
memerlukan data yang sudah terurut sehingga sistem dapat langsung mencari NIM atau 
nama praktikan pada urutan data yang tersedia. 
Hasil pengujian tersebut sesuai dengan karakteristik Sequential Search  yang 
memeriksa elemen secara berurutan. Waktu pencarian cenderung meningkat ketika 
jumlah data bertambah, tetapi hasil pengujian menunjukkan bahwa algoritma masih dapat 
memproses dataset 5.000 dengan waktu di bawah 5 ms. Penerapan tersebut mendukung 
kebutuhan pencarian data praktikan pada lapisan aplikasi tanpa mewajibkan proses 
pengurutan sebelumnya.  
 
4.5.3 Perbandingan Algoritma dengan Baseline MySQL 
Hasil perbandingan menunjukkan bahwa algoritma aplikasi dan baseline MySQL 
memiliki karakteristik pemrosesan yang berbeda. Merge Sort  dan Sequential Search  
bekerja setelah data tersedia pada memori aplikasi. MySQL ORDER BY  dan 
WHERE/LIKE bekerja melalui query yang melibatkan pembacaan data dari basis data 
serta pengiriman hasil ke aplikasi. 
--- PAGE 125 ---
 
103 
 
Merge Sort  menghasilkan waktu rata -rata yang lebih rendah dibandingkan 
MySQL ORDER BY pada seluruh ukuran dataset. Dataset 100 menghasilkan rata -rata 
waktu Merge Sort sekitar 0,449815 ms dan MySQL ORDER BY sekitar 10,111763 ms. 
Dataset 5.000 menghasilkan rata-rata waktu Merge Sort sekitar 45,504172 ms, sedangkan 
MySQL ORDER BY membutuhkan sekitar 80,137558 ms. 
Perbedaan tersebut terjadi karena Merge Sort hanya mengurutkan data yang telah 
dimuat ke memori aplikasi. MySQL ORDER BY harus menjalankan query, membaca data 
dari tabel, mengurutkan data, dan mengembalikan hasilnya ke aplikasi. Hasil ini tidak 
menunjukkan bahwa Merge Sort  dapat menggantikan MySQL, tetapi menunjukkan 
keuntungan pemrosesan pada lapisan aplikasi ketika data sudah tersedia di memori. 
Sequential Search juga menghasilkan waktu lebih rendah dibandingkan MySQL 
WHERE/LIKE. Rata-rata waktu Sequential Search meningkat dari sekitar 0,043898 ms 
pada dataset 100 menjadi 2,534457 ms pada dataset 5.000. MySQL WHERE/LIKE 
meningkat dari sekitar 10,204491 ms menjadi 55,276125 ms pada ukuran dataset yang 
sama. 
Perbandingan pencarian perlu mempertimbangkan lokasi pemrosesan data. 
Sequential Search  memeriksa data yang telah tersedia di aplikasi, sedangkan MySQL 
WHERE/LIKE melakukan pencarian secara langsung pada basis data. MySQL tetap 
berperan penting ketika sistem membutuhkan data terbaru yang belum dimuat ke aplikasi, 
sedangkan Sequential Search  mendukung pencarian lanjutan terhadap kumpulan data 
yang telah tersedia. 
 
4.5.4 Analisis Waktu Eksekusi, Memori, dan Pembersihan Data 
Waktu eksekusi menunjukkan durasi yang dibutuhkan setiap metode untuk 
menyelesaikan proses pengurutan atau pencarian. Merge Sort mengalami kenaikan waktu 
karena seluruh data harus dibagi dan digabungkan kembali. Sequential Search mengalami 
kenaikan waktu ketika sistem harus memeriksa lebih banyak elemen. Baseline MySQL 
membutuhkan waktu tambahan karena prosesnya melibatkan komunikasi antara aplikasi 
dan basis data. 
Penggunaan memori menunjukkan tambahan sumber daya selama pengujian 
berlangsung. Merge Sort menggunakan memori yang meningkat dari sekitar 6,6328 KB 
--- PAGE 126 ---
 
104 
 
menjadi 301,8672 KB. Sequential Search menggunakan memori yang rendah dan relatif 
stabil. MySQL ORDER BY  menggunakan memori paling besar hingga mencapai 
3.863,9141 KB pada dataset 5.000, sedangkan penggunaan memori MySQL 
WHERE/LIKE bergantung pada jumlah data yang dikembalikan oleh query. 
Skenario kata kunci kosong pada MySQL WHERE/LIKE menggunakan memori 
lebih besar karena query mengembalikan seluruh data. Skenario kata kunci ditemukan, 
tidak ditemukan, dan duplikat menggunakan memori lebih rendah karena hasil query yang 
dikembalikan lebih sedikit. Kondisi tersebut menunjukkan bahwa penggunaan memori 
MySQL dipengaruhi oleh jumlah data hasil query, bukan hanya jumlah data yang tersedia 
pada dataset. 
Sistem menjalankan 3.200 pengujian utama dari seluruh kombinasi metode, 
ukuran dataset, dan skenario. Metode IQR mengeluarkan 129 hasil yang berada di luar 
batas kewajaran, sehingga sebanyak 3.071 hasil bersih digunakan dalam statistik dan 
grafik. Proses pembersihan tersebut mengurangi pengaruh lonjakan waktu yang dapat 
terjadi akibat kondisi sementara pada server atau lingkungan pengujian. 
Nilai mean menunjukkan rata -rata hasil pengujian, median menunjukkan nilai 
tengah, dan standar deviasi menunjukkan tingkat penyebaran hasil. Nilai mean dan 
median yang berdekatan menunjukkan hasil yang relatif konsisten, sedangkan standar 
deviasi yang lebih besar menunjukkan variasi waktu yang lebih tinggi. Penggunaan 
beberapa ukuran statistik membuat hasil pengujian tidak hanya bergantung pada satu nilai 
rata-rata.

KESIMPULAN DAN SARAN 
 
5.1 Kesimpulan 
Penelitian ini menghasilkan sistem pengelolaan Praktikum Fisika Dasar berbasis 
web dengan penerapan Merge Sort  dan Sequential Search . Berdasarkan hasil 
implementasi dan pengujian, kesimpulan penelitian ini adalah sebagai berikut. 
1. Sistem berhasil mengelola data praktikan, asisten, periode, kelompok, materi, 
jadwal, presensi, penilaian, dan nilai akhir secara terpusat. Hasil Black Box Testing 
menunjukkan bahwa fitur utama dan pembagian hak akses berjalan sesuai 
rancangan. 
2. Merge Sort  berhasil mengurutkan data praktikan berdasarkan program studi dan 
NIM. Waktu eksekusi meningkat dari 0,383057  – 0,592618 ms pada 100 data 
menjadi 27,659516 –65,071449 ms pada 5.000 data. Penggunaan memorinya 
meningkat dari sekitar 6,6328 KB menjadi 301,8672 KB. 
3. Sequential Search  berhasil mencari data berdasarkan NIM atau nama tanpa 
memerlukan data terurut. Waktu eksekusi berada pada rentang 0,005438–0,064261 
ms pada 100 data dan 0,009820 –4,533239 ms pada 5.000 data. Penggunaan 
memorinya relatif stabil pada kisaran 0,3672–0,5000 KB. 
4. Hasil pengujian menunjukkan bahwa Merge Sort dan Sequential Search memiliki 
waktu eksekusi serta penggunaan memori lebih rendah dibandingkan baseline 
MySQL pada lingkungan pengujian. Kedua algoritma tersebut melengkapi fungsi 
MySQL dalam pengolahan data pada lapisan aplikasi. 
 
5.2  Saran 
Penelitian ini masih dapat dikembangkan melalui penambahan ukuran dataset, 
perluasan variasi skenario pengujian, dan peningkatan fitur sistem. Pengembangan 
tersebut dapat memberikan gambaran kinerja Merge Sort, Sequential Search, dan baseline 
MySQL pada kondisi yang lebih beragam. Berdasarkan hasil penelitian, beberapa saran 
yang dapat dipertimbangkan adalah sebagai berikut.
